## 2024-05-24 - Overly Permissive CORS with Credentials
**Vulnerability:** The application is using `origin: '*'` together with `credentials: true` in Hono CORS configuration (`src/worker/routes/auth-routes.ts`).
**Learning:** Using a wildcard origin with credentials enabled allows any website to make requests to the authenticated endpoints and include the user's cookies/credentials. This is a significant security risk and can lead to CSRF attacks or data theft.
**Prevention:** Avoid using `origin: '*'` with `credentials: true`. Instead, implement a dynamic origin resolver function utilizing `c.env` or `import.meta.env` to strictly validate against allowed frontend URLs and development environments.
## 2026-07-23 - Enhance SSRF protections in URL validator
**Vulnerability:** URL validator missed link-local addresses (169.254.x.x), 0.0.0.0, IPv6 loopback ([::1] and ::1), and internal domains (.local, .internal), leaving cloud environment metadata and internal services exposed to SSRF.
**Learning:** Basic SSRF protections that only check for standard private IPv4 blocks (10.x, 172.16.x, 192.168.x) and localhost often miss cloud-specific metadata IP ranges (169.254.x.x) and alternative loopbacks/internal domains. Furthermore, JavaScript's URL object handles IPv6 addresses peculiarly, depending on the runtime environment (Node vs browser vs Bun) — typically retaining brackets in .hostname for [::1], but it is safer to check for both [::1] and ::1.
**Prevention:** When validating URLs to prevent SSRF, comprehensively block link-local addresses, all forms of loopback (0.0.0.0, [::1], ::1), and internal-use domains alongside standard private IP spaces.
