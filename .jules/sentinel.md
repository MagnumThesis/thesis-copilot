## 2024-05-24 - Overly Permissive CORS with Credentials
**Vulnerability:** The application is using `origin: '*'` together with `credentials: true` in Hono CORS configuration (`src/worker/routes/auth-routes.ts`).
**Learning:** Using a wildcard origin with credentials enabled allows any website to make requests to the authenticated endpoints and include the user's cookies/credentials. This is a significant security risk and can lead to CSRF attacks or data theft.
**Prevention:** Avoid using `origin: '*'` with `credentials: true`. Instead, implement a dynamic origin resolver function utilizing `c.env` or `import.meta.env` to strictly validate against allowed frontend URLs and development environments.

## 2025-03-09 - Incomplete SSRF Protection in URL Validation
**Vulnerability:** The application's `validateAndSanitizeUrl` function attempted to prevent Server-Side Request Forgery (SSRF) by blocking common private IPs (`127.0.0.1`, `192.168.x.x`, `10.x.x.x`) but failed to block cloud metadata addresses (`169.254.x.x`), IPv6 loopback (`[::1]`), `0.0.0.0`, and internal domains (`.internal`, `.local`).
**Learning:** Basic regex matching for IPv4 addresses is insufficient for comprehensive SSRF prevention. Attackers can bypass these filters using alternative IP representations or exploiting unblocked ranges like cloud metadata IPs, which are particularly dangerous in cloud environments as they can expose sensitive instance metadata and credentials.
**Prevention:** Implement comprehensive hostname validation that includes all reserved, local, and link-local IP addresses (both IPv4 and IPv6), cloud metadata IPs, and internal Top-Level Domains (TLDs). Ensure that URL canonicalization is handled correctly so alternative representations (like octal or hex IPs) are resolved and blocked by the native `URL` constructor before hostname string validation.
