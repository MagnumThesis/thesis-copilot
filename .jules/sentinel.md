## 2024-05-24 - Overly Permissive CORS with Credentials
**Vulnerability:** The application is using `origin: '*'` together with `credentials: true` in Hono CORS configuration (`src/worker/routes/auth-routes.ts`).
**Learning:** Using a wildcard origin with credentials enabled allows any website to make requests to the authenticated endpoints and include the user's cookies/credentials. This is a significant security risk and can lead to CSRF attacks or data theft.
**Prevention:** Avoid using `origin: '*'` with `credentials: true`. Instead, implement a dynamic origin resolver function utilizing `c.env` or `import.meta.env` to strictly validate against allowed frontend URLs and development environments.
## 2024-05-18 - SSRF protection bypass on basic private IP filtering
**Vulnerability:** The existing URL validation (`validateAndSanitizeUrl`) blocked some private IPs like `127.x.x.x` and `10.x.x.x`, but it allowed link-local addresses (`169.254.x.x`), the unspecified address (`0.0.0.0`), IPv6 loopbacks (`[::1]`), and internal domain names (`.internal`, `.local`). This allows an attacker to bypass SSRF protections and potentially access sensitive cloud metadata services or internal endpoints.
**Learning:** Basic regex or prefix matching for `localhost` or standard private subnets is insufficient to stop modern SSRF attacks. Node.js/Browsers URL canonicalization and various alternative local representations (e.g. `0.0.0.0`) must be comprehensively denied.
**Prevention:** Always use a comprehensive deny-list of private, local, link-local, and broadcast IP ranges as well as local/internal TLDs. When validating URLs for outbound requests, ensure protections cover AWS metadata (`169.254.169.254`), generic loopbacks, and alternative zero-routing IPs.
