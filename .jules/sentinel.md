## 2024-05-24 - Overly Permissive CORS with Credentials
**Vulnerability:** The application is using `origin: '*'` together with `credentials: true` in Hono CORS configuration (`src/worker/routes/auth-routes.ts`).
**Learning:** Using a wildcard origin with credentials enabled allows any website to make requests to the authenticated endpoints and include the user's cookies/credentials. This is a significant security risk and can lead to CSRF attacks or data theft.
**Prevention:** Avoid using `origin: '*'` with `credentials: true`. Instead, implement a dynamic origin resolver function utilizing `c.env` or `import.meta.env` to strictly validate against allowed frontend URLs and development environments.
## 2026-09-08 - SSRF Vulnerability in URL Metadata Extractor
**Vulnerability:** The URL metadata extractor (`validateAndSanitizeUrl`) used naive string matching (`.startsWith('127.')`) to block local and private IPs, leaving it vulnerable to SSRF via AWS metadata (`169.254.169.254`), ANY address (`0.0.0.0`), IPv6 loopback variants (`[::1]`, `[::ffff:127.0.0.1]`, `[fc00::]`, `[fe80::]`), and domain bypasses (e.g., `127.com`).
**Learning:** Naive string prefix checking on hostnames is insufficient for SSRF protection as it blocks legitimate domains and fails to account for alternative IP representations (IPv6, metadata endpoints). The native `URL` object canonicalization does not automatically map these representations to standard IPv4 localhost/private strings.
**Prevention:** Explicitly block cloud provider metadata IPs, the `0.0.0.0` address, IPv6 loopback/ULA/Link-local ranges, and use precise regex boundaries instead of `.startsWith()` when checking IPv4 ranges.
