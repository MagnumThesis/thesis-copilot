## 2024-05-24 - Overly Permissive CORS with Credentials
**Vulnerability:** The application is using `origin: '*'` together with `credentials: true` in Hono CORS configuration (`src/worker/routes/auth-routes.ts`).
**Learning:** Using a wildcard origin with credentials enabled allows any website to make requests to the authenticated endpoints and include the user's cookies/credentials. This is a significant security risk and can lead to CSRF attacks or data theft.
**Prevention:** Avoid using `origin: '*'` with `credentials: true`. Instead, implement a dynamic origin resolver function utilizing `c.env` or `import.meta.env` to strictly validate against allowed frontend URLs and development environments.
## 2026-10-10 - Dynamic Origin Resolver Returning Wildcard with Credentials
**Vulnerability:** The dynamic origin resolver in `src/worker/utils/cors-resolver.ts` fell back to returning `*` when the `origin` header was not provided or was not in the allowed origins array. When combined with `credentials: true` (e.g., in Hono `cors` middleware), this is a critical security vulnerability and violates CORS standards, often resulting in blocked requests by modern browsers but historically allowed overly permissive access.
**Learning:** Even when using a dynamic origin resolver to validate explicit origins, the fallback for missing or unknown origins must never be `*` if the endpoint uses authentication credentials.
**Prevention:** If an origin is omitted or unknown, return `undefined` (or a specific default trusted origin) instead of `*` to force the CORS middleware to either omit the `Access-Control-Allow-Origin` header or respond securely, preventing wildcard credential sharing.
