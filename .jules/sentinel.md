## 2024-05-24 - Overly Permissive CORS with Credentials
**Vulnerability:** The application is using `origin: '*'` together with `credentials: true` in Hono CORS configuration (`src/worker/routes/auth-routes.ts`).
**Learning:** Using a wildcard origin with credentials enabled allows any website to make requests to the authenticated endpoints and include the user's cookies/credentials. This is a significant security risk and can lead to CSRF attacks or data theft.
**Prevention:** Avoid using `origin: '*'` with `credentials: true`. Instead, implement a dynamic origin resolver function utilizing `c.env` or `import.meta.env` to strictly validate against allowed frontend URLs and development environments.
## 2024-05-24 - Missing Authentication and IDOR on Auth Routes
**Vulnerability:** The `/profile/:userId` and `/change-password/:userId` routes in `src/worker/routes/auth-routes.ts` were lacking the `requireAuth` middleware, and the handlers in `src/worker/handlers/auth.ts` did not verify if the requested `userId` matched the authenticated user's ID. This constituted a critical Insecure Direct Object Reference (IDOR) and unauthorized access vulnerability.
**Learning:** Even within an "auth" module, routes that perform actions on a specific user's behalf must explicitly enforce authentication at the router level and verify object ownership (authorization) at the handler level.
**Prevention:** Always apply `requireAuth` to protected routes and consistently use `getAuthContext(c)` to validate `authContext.userId === requestedUserId` in all handlers accessing user-specific resources to prevent IDOR attacks.
