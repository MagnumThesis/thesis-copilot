## 2024-05-24 - Overly Permissive CORS with Credentials
**Vulnerability:** The application is using `origin: '*'` together with `credentials: true` in Hono CORS configuration (`src/worker/routes/auth-routes.ts`).
**Learning:** Using a wildcard origin with credentials enabled allows any website to make requests to the authenticated endpoints and include the user's cookies/credentials. This is a significant security risk and can lead to CSRF attacks or data theft.
**Prevention:** Avoid using `origin: '*'` with `credentials: true`. Instead, implement a dynamic origin resolver function utilizing `c.env` or `import.meta.env` to strictly validate against allowed frontend URLs and development environments.
## 2026-10-28 - SSRF Vulnerability in Metadata Extraction
**Vulnerability:** Weak URL sanitization in `url-metadata-extractor.ts` failed to prevent SSRF against IPv6 loopback (`[::1]`) and AWS metadata endpoints (`169.254.169.254`). It also used broad string matching like `.startsWith('127.')` which could block valid subdomains (e.g., `test127.com`) or miss non-standard IP formats like decimal or hex (which the `URL` object canonicalizes, though the regex needs to check the canonicalized hostname).
**Learning:** Node's `URL` object canonicalizes integer/hex IPs (e.g., `2130706433` to `127.0.0.1`), but regex validation on `urlObj.hostname` must explicitly account for embedded IP strings to prevent DNS-based SSRF (e.g., `127.0.0.1.nip.io`). Also, AWS metadata and IPv6 loopbacks are commonly overlooked.
**Prevention:** Use precise regex patterns (e.g., `/(^|\.)127\.\d+\.\d+\.\d+(?:\.|$)/`) for IPv4 ranges, explicitly check for `[::1]`, and include link-local (`169.254.169.254`) ranges. Avoid broad `.includes()` or `.startsWith()` for IP address validation.
