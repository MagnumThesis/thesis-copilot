## 2024-05-24 - Overly Permissive CORS with Credentials
**Vulnerability:** The application is using `origin: '*'` together with `credentials: true` in Hono CORS configuration (`src/worker/routes/auth-routes.ts`).
**Learning:** Using a wildcard origin with credentials enabled allows any website to make requests to the authenticated endpoints and include the user's cookies/credentials. This is a significant security risk and can lead to CSRF attacks or data theft.
**Prevention:** Avoid using `origin: '*'` with `credentials: true`. Instead, implement a dynamic origin resolver function utilizing `c.env` or `import.meta.env` to strictly validate against allowed frontend URLs and development environments.

## 2024-05-24 - Missing Authentication and IDOR on User Endpoints
**Vulnerability:** Protected user endpoints (`/profile/:userId`, `/change-password/:userId`, etc.) were missing the `requireAuth` middleware in the routing configuration, and the corresponding handlers failed to verify that the requested `userId` matched the authenticated user's ID. This allows any user to read, update, or change the password of any other user's account by simply changing the `userId` in the URL parameter.
**Learning:** Even if a route is placed under a "Protected routes" comment block, the middleware must be explicitly applied. Furthermore, authentication is not enough; authorization (ownership verification) must be strictly enforced on parameterized routes to prevent Insecure Direct Object Reference (IDOR) vulnerabilities.
**Prevention:** Always apply the `requireAuth` middleware to protected routes. Inside handlers for parameterized user resources, always retrieve the authenticated user context (`getAuthContext(c)`) and explicitly validate that `authContext.userId === requestedUserId`. Default to a "fail-closed" approach (`if (!authContext || authContext.userId !== userId)`).
