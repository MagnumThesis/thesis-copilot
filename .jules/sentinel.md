## 2024-05-24 - Overly Permissive CORS with Credentials
**Vulnerability:** The application is using `origin: '*'` together with `credentials: true` in Hono CORS configuration (`src/worker/routes/auth-routes.ts`).
**Learning:** Using a wildcard origin with credentials enabled allows any website to make requests to the authenticated endpoints and include the user's cookies/credentials. This is a significant security risk and can lead to CSRF attacks or data theft.
**Prevention:** Avoid using `origin: '*'` with `credentials: true`. Instead, implement a dynamic origin resolver function utilizing `c.env` or `import.meta.env` to strictly validate against allowed frontend URLs and development environments.
## 2024-10-24 - Missing Auth and IDOR in Protected Routes\n**Vulnerability:** Protected routes in `src/worker/routes/auth-routes.ts` (`/profile/:userId`, `/change-password/:userId`) did not use the `requireAuth` middleware, and their corresponding handlers in `src/worker/handlers/auth.ts` did not validate that the requested `userId` matched the authenticated `userId`, leading to a critical IDOR vulnerability where any user could access or modify another user's profile and password.\n**Learning:** Routes with dynamic parameters indicating ownership (like `:userId`) must be guarded by both authentication middleware and explicit authorization checks ensuring the authenticated context matches the requested resource. A 'fail-closed' approach must be used.\n**Prevention:** Always apply authentication middleware to protected routes and consistently enforce ownership validation in handlers using `if (!authContext || authContext.userId !== userId)` to prevent unauthorized access.\n
